# Mutation Testing Tool & Config

To run our mutation testing, we used mutmut for Python. This required some configuration to get both mutmut and pytest to run reliably, without causing errors and crashes. We mainly had to configure mutmut (by updating pyproject.toml) to ignore certain files that caused a range of issues for it, and focus on the actual project code while ignoring supporting files. Similarly, we had to configure pytest to ignore any autogenerated mutmut files that caused it issues. Screenshots of our initial and updated mutmut mutation testing summaries are included in this folder (courseProjectDocs/mutation-testing), with summaries and analyses included below.

# Updated Mutation Testing Score

Mutation Score: 77/176 (43.75%)

Analysis:
    Considering the fact that pyinstrument did not have any pre-existing mutation testing, it was unsurprising that our initial mutation score for middleware.py was rather low, with 74 of the total 176 mutants (42.05%) for middleware being caught by the existing tests. From examining some of the uncaught mutants, it seems that a lot of the surviving mutants were able to sneak through the existing tests by altering middleware state or behavior that the rest of the project simply trusts will work as expected. This lines up well with what we saw during the unit testing activities, where it appears that the developers have a lot of blind trust in various components and subsystems, especially in existing components that the copied from another source.

    To add to the mutation testing of middleware, we added a new test to explicitly catch and kill the first uncaught mutant listed by mutmut that modified line 41 to remove the None default value of a getattr() call of PYINSTRUMENT_SHOW_CALLBACK:

    Original:
    ```
        func_or_path = getattr(settings, "PYINSTRUMENT_SHOW_CALLBACK", None)
    ```

    Mutated:
    ```
        func_or_path = getattr(settings, "PYINSTRUMENT_SHOW_CALLBACK")
    ```

    The updated test is able to catch this mutant, by explicitly verifying that profile_request() runs without any errors being thrown even when no settings attribute is provided for PYINSTRUMENT_SHOW_CALLBACK. In the original middleware component, the default value of None for settings allows process_request() to run normally. However, in the mutated version of middleware, without a default None setting, process_request() does throw an error, which causes this test to fail.

    Coincidentally, adding this test successfully caught 2 additional middleware mutants that were not explicitly targeted by the additional test, increasing the caught mutant total to 77/176 (43.75%) for middleware.py.
